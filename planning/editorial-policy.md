# 編集方針

作成日：2026-11-02。対象：Siki 1.0.0。状態：基本方針を合意済み、ページ構成と検証方法の初期案。

## 読者と対象範囲

初めて使う人が「導入して板を開き、読み書きできる」ことと、既存の利用者が目的の操作・設定を探せることを両立します。板・スレッド・レスなどの用語は、最初の説明と用語への案内で補います。

本文では1.0.0でできることと操作を説明します。「以前はこうだった」という説明は、原則として移行ガイドへ置きます。設定の適用範囲や元に戻す方法は、操作に必要な情報として本文に含めます。

| 含める内容 | 役割 |
| --- | --- |
| 導入、画面の見方、閲覧・投稿 | 最初の利用を完了できるようにする |
| 検索、NG、画像、お気に入り、ワークスペースなど | 目的別に使い方を探せるようにする |
| 設定、テーマ、スキン、操作割り当て、ユーザーコマンド、プラグインの利用 | 自分の使い方に合わせて調整できるようにする |
| トラブル対処、バックアップ、移行 | 状態を確認し、回復や引き継ぎができるようにする |
| 設定・コマンド等のリファレンス | 正確な名称、意味、適用条件を調べられるようにする |

公式サイトのトップ、配布ファイル一覧、過去版アーカイブ、更新履歴配信、問い合わせページは移行対象外です。必要な場面から既存の公式ページへ案内します。プラグイン開発APIなどの開発者資料は資料台帳に残し、利用者向け本文を整えた後に配置と範囲を検討します。

2026-11-03の追加依頼により、[寄付・開発支援](../manual/donate.md)を掲載対象に加えました。参照元の `../siki-manual/docs/donate.md` にあるKo-fi・Amazonギフト券・Bitcoinの案内をもとに、支援方法を説明します。

## 1.0.0と準備版の扱い

- 公開する本文の対象は1.0.0とします。0.99.xの動作を確認しただけで「1.0.0確認済み」とはしません。
- 準備版で確認できる内容から執筆し、確認したバージョン・日付・範囲を編集用の記録へ残します。
- 実装の存在、操作確認、外部サービスとの接続確認を分けます。ソースで見つけた機能の存在だけで、操作や接続が成功すると断定しません。
- 未実装・計画段階の機能を利用可能な機能として説明しません。仕様が定まらない箇所は編集資料へ記録します。
- 1.0.0確定時に、準備版で確認したページと、その後に変更された機能を再確認します。
- 初版は1.0.0のマニュアルです。将来の1.xでの対象範囲拡大や版別公開は、その際に運用を決めます。

## 根拠と出典

確認先は、対象版の実機操作・実装・既定値、リリースノート、既存の公式資料、非公式Wikiです。実機と実装が食い違う場合は、操作条件と差異を記録し、原因が分かるまで未確認として扱います。

既存資料は、説明の材料と確認すべき論点として利用します。旧画面の設定名、既定値、ショートカット、対応サイト、配布形式はそのまま引き継ぎません。リリースノートも、現在の仕様が維持されているかを確認します。

Wikiの本文・画像・投稿の転載は、出典と利用条件を確認したうえで扱います。利用者の疑問を抽出し、実際の操作を確認して新しい説明を書きます。必要な外部資料へのリンクと参照日を残します。

非公開の実装の引用、内部パス、コミット情報、検証記録は、利用者向け本文へ機械的に混ぜません。GitHubで公開する計画資料にも、認証情報・個人情報・非公開ソース本文は置きません。

## 文章とページ構成

- 1ページで主に1つの目的を扱います。分割しすぎて手順が途切れる場合はまとめます。
- 冒頭で何ができるかを示し、必要条件、操作、結果、適用範囲、戻す方法の順で説明します。
- 画面の項目名を正確に記載します。同じ概念に複数の呼び方がある場合は、代表語に統一して別名を補います。
- 説明は設定項目の列挙だけにせず、「何を変えると、どこが変わるか」を示します。
- OS、配布形式、サイトによる違いは、その手順に必要な位置で明記します。
- 既定のショートカットと利用者が変更した割り当てを区別します。メニューなど別の入口も必要に応じて示します。
- 本文に一般的な操作と説明を置き、詳細な一覧・識別子・構文はリファレンスへ案内します。
- 「ここ」「同上」だけで参照せず、操作対象や機能名を記載します。

ページの共通構成は[雛形](page-template.md)を参照してください。説明に必要のない節は省略できます。

## 画像と画面確認

説明に必要な場面で新しいスクリーンショットを作成します。操作名や結果は本文でも説明し、画像に代替テキストを付けます。個人情報や認証情報を写さず、配布・転載条件も確認します。

アプリ画面の画像は基準テーマを1つ決めてそろえます。実機操作と撮影はSiki側のAGENTS.mdおよびWindows computer-useの手順に従います。異なるOSの操作を説明するときは、確認した環境を記録します。

サイトの表示は基準テーマ1つと狭い画面幅で確認します。キーボード操作、フォーカス、見出し構造、検索からページへの移動も確認します。

## 原稿と公開対象

`manual/` を公開用原稿の正本にします。アプリ側の `docs/manual/` と旧 `siki-manual` は当面の参照元です。新版へ取り込んだ説明を複数の場所で継続編集する運用にはしません。参照元への案内追加は移行作業として別途行います。

`planning/` はサイトのビルドとサイト内検索から除外します。旧版資料、執筆用メモ、未確認の草稿も新版の検索に混在させません。リポジトリ自体の公開範囲と、サイト掲載対象は別に管理します。

## 将来のRAGのために保つこと

本文はMarkdownを基本にし、独自コンポーネントだけに重要な説明を持たせません。安定したページパス、意味のある見出し、用語の統一、説明可能な表、画像の代替テキストを使います。

本文のタイトル・概要と、サイト全体の対象版を明確にします。検証日や確認版は編集用に記録し、必要なものだけ本文へ表示します。RAG専用の分割、埋め込み、データ出力形式は今回設計しません。
