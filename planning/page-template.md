# ページの雛形

操作説明の基本構成です。すべての節を埋める必要はありません。リファレンスでは、仕様・値・例・制限を中心に組み替えます。

## 公開本文の例

以下のコードブロックは構成例です。山括弧内は記入欄です。未記入のまま公開用の本文や検索対象にしません。

```markdown
---
title: <目的が分かるページ名>
description: <このページでできるようになること>
---

# <目的が分かるページ名>

<何に使う機能か、どの場面で使うかを1〜2文で説明する。>

## 始める前に

<必要な設定、対象のOS・配布形式・サイト、準備するデータ。>

## 操作する

1. <入口と操作対象を具体的に書く。>
2. <画面に表示される名称で操作を説明する。>
3. <確定や保存が必要な場合は、その方法を書く。>

<操作後に何が表示・保存・反映されるかを書く。>

## 適用範囲と戻し方

<現在のタブだけか、サイト・板・共通の設定かを説明する。>
<自動保存か、再起動や開き直しが必要かを書く。>
<解除・復元・初期値への戻し方を説明する。>

## うまくいかないとき

<この操作に固有の原因と確認方法を書く。共通の対処は関連ページへ案内する。>

## 関連する操作

<関連するページへの、目的が分かる名前のリンクを置く。>
```

frontmatterの細かな表示方法はVitePress試作で確認します。対象版はサイト全体で示し、ページ単独で誤解が生じる例外だけ本文に明記します。検証状況を公開用frontmatterへ大量に持ち込まず、編集記録と分けます。

## 編集用の検証記録

本文の作成を始めたら、対応する記録を `planning/verification/` に作成します。次は記録例で、実際の確認結果ではありません。

```yaml
page: manual/customization/settings.md
status: drafting
target_version: 1.0.0
sources:
  - M36
  - D08
  - N01
checked_version: null
checked_date: null
environment: null
code_checked: false
ui_checked: false
open_questions:
  - 共通設定とタブの個別指定を解除した際の反映を確認する
```

資料IDは[既存資料との対応表](source-map.md)を参照します。`checked_version` などは実際に確認した後に記入し、未確認のまま日付や版を埋めません。コード確認と実機確認は別々に記録します。非公開の詳細が必要な記録は、公開可能な結論と分けて管理します。

## 原稿の状態

| 状態 | 意味 |
| --- | --- |
| `drafting` | 原稿作成・資料の照合中 |
| `checking` | 対象条件の操作確認中。疑問点が残っている |
| `checked-pre-release` | 指定した準備版・環境・範囲で確認済み。1.0.0確認済みではない |
| `checked-1.0.0` | 1.0.0で必要な操作と仕様の確認を完了した |

ページの掲載対象から外す判断は、資料の対応表に理由と行き先を記録します。状態名だけで不明点を省略せず、確認できていない条件を記載します。
